## LAYOUT IT EXPECTS

```
WORKDIR/
  slides/        18 PNG: 01..15 ANSWERS, PLUS 01a, 04a, 09a QUESTION SLIDES
  voicenotes/    15 RECORDINGS, ONE PER ANSWER SLIDE
```

FILENAMES ARE MATCHED LOOSELY: `Slide 7.wav`, `slide_7.wav`, `07.wav`, `7.m4a`
AND `Slide07.mp3` ALL RESOLVE TO SLIDE 7. CONTAINERS: wav m4a mp3 aac flac ogg
opus webm.

## RUN IT

```

python3 BUILD_VIDEO.py            BUILD
python3 BUILD_VIDEO.py --force    IGNORE THE CACHE AND RECONDITION EVERY TAKE
python3 BUILD_VIDEO.py --meta     REWRITE chapters.json AND timeline.csv ONLY
```

LOCALLY ON WINDOWS THIS IS USUALLY FASTER THAN COLAB, BECAUSE THE RECORDINGS ARE
ABOUT 130 MB AND WOULD HAVE TO BE UPLOADED FIRST.

## AUDIO CONDITIONING, PER SLIDE

1. HIGHPASS AT 70 Hz, TO DROP DESK RUMBLE AND BREATH THUMP
2. OPTIONAL FFT DENOISE, OFF BY DEFAULT; `CML_DENOISE=1` ENABLES IT
3. LEADING AND TRAILING SILENCE TRIMMED AT -50 dB PEAK
4. TWO PASS EBU R128 LOUDNESS NORMALISATION TO I = -16 LUFS, TP = -1.5 dBTP.
   TWO PASS MATTERS: A SINGLE PASS IS DYNAMIC AND PUMPS THE QUIET SLIDES
5. RESAMPLED TO 48 kHz STEREO s16 SO EVERY SEGMENT CONCATENATES CLEANLY
6. 0.25 s OF LEAD IN AND 0.60 s OF LEAD OUT, SO CUTS NEVER CLIP SPEECH

THE THREE QUESTION SLIDES ARE NOT NARRATED. EACH IS HELD IN DIGITAL SILENCE FOR
`CML_QUESTION_HOLD` SECONDS, DEFAULT 8.

## CHECKS, ALL FATAL UNLESS STATED

- EVERY ANSWER SLIDE MUST HAVE EXACTLY ONE RECORDING
- A RECORDING THAT MATCHES NO SLIDE IS AN ERROR, NOT A SILENT SKIP
- TWO RECORDINGS CLAIMING THE SAME SLIDE IS AN ERROR
- LOUDNORM RETURNING A NON FINITE MEASUREMENT IS AN ERROR; THAT MEANS THE TAKE
  IS SILENT
- A TAKE SHORTER THAN 0.35 OF THE MEDIAN IS REPORTED AS A LIKELY TRUNCATED
  RECORDING. IT IS A WARNING; `CML_STRICT=1` PROMOTES IT TO FATAL
- THE CONCATENATED AUDIO MUST MATCH THE PLANNED TIMELINE TO 0.25 s
- THE FINISHED MP4 MUST MATCH THE PLANNED TIMELINE TO 0.5 s

## SETTINGS, ALL ENVIRONMENT VARIABLES

| VARIABLE | DEFAULT | MEANING |
|---|---|---|
| `CML_SLIDES` | `./slides` | SLIDE PNG DIRECTORY |
| `CML_VOICE` | `./voicenotes` | RECORDINGS DIRECTORY |
| `CML_WORK` | `./build` | SCRATCH AND PER SLIDE WAV CACHE |
| `CML_OUT` | `./CML6032_Assignment1_Nisheal_2025CYS7090.mp4` | OUTPUT |
| `CML_QUESTION_HOLD` | `8.0` | SECONDS EACH QUESTION SLIDE IS HELD |
| `CML_HEAD_PAD` / `CML_TAIL_PAD` | `0.25` / `0.60` | LEAD IN AND LEAD OUT |
| `CML_DENOISE` | `0` | `1` ENABLES A GENTLE FFT DENOISE |
| `CML_CRF` | `20` | H.264 QUALITY, LOWER IS BIGGER AND BETTER |
| `CML_ABR` | `160k` | AAC BITRATE |
| `CML_FPS` | `30` | FRAME RATE |
| `CML_STRICT` | `0` | `1` MAKES A SUSPICIOUSLY SHORT TAKE FATAL |
| `CML_NVENC` | `1` | `0` FORCES LIBX264 EVEN IF NVENC EXISTS |

## IF YOU RE-RECORD A SLIDE LATER

1. DROP THE NEW TAKE INTO `voicenotes/` UNDER THE SAME SLIDE NUMBER
2. `python3 BUILD_VIDEO.py` - ONLY THAT TAKE IS RECONDITIONED, THE REST IS CACHED
3. COPY THE NEW MP4 AND `chapters.json` INTO `docs/`
4. REFRESH THE HARD CODED FALLBACK TABLE IN `docs/index.html` FROM THE NEW
   `chapters.json`, SO THE CHAPTER STRIP STAYS RIGHT EVEN IF THE FETCH FAILS

AT 55.4 MB THE MP4 IS UNDER THE 100 MB GITHUB BLOB LIMIT, SO IT IS COMMITTED
DIRECTLY. GITHUB WARNS ABOVE 50 MB BUT DOES NOT REFUSE. DO NOT USE GIT LFS:
GITHUB PAGES SERVES THE LFS POINTER TEXT AND NOT THE FILE.
