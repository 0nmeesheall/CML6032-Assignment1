## ONE-TIME SETUP

1. BUILD THE VIDEO WITH `video/BUILD_VIDEO.py`, OR WITH
   `video/CML6032_video_colab.ipynb` IF YOU PREFER COLAB. A CPU RUNTIME IS
   ENOUGH; THERE IS NO TEXT-TO-SPEECH AND NO GPU IN THIS PIPELINE ANY MORE.
2. COPY THE TWO OUTPUTS INTO THIS FOLDER, KEEPING THE NAMES EXACTLY:
   - `CML6032_Assignment1_Nisheal_2025CYS7090.mp4`
   - `chapters.json`
3. COMMIT AND PUSH.
4. IN THE REPOSITORY, OPEN SETTINGS > PAGES. SET SOURCE TO "DEPLOY FROM A BRANCH",
   BRANCH `main`, FOLDER `/docs`. SAVE AND WAIT ABOUT ONE MINUTE.
5. OPEN THE LIVE URL IN A PRIVATE WINDOW AND CONFIRM THE VIDEO PLAYS WHILE
   LOGGED OUT. THE REPOSITORY MUST BE PUBLIC.

## WHY PAGES AND NOT A PLAIN REPOSITORY FILE

GITHUB PAGES SERVES THE MP4 WITH THE CORRECT MIME TYPE, SO IT STREAMS IN THE
BROWSER ON CLICK. A FILE LINKED FROM THE REPOSITORY TREE IS HANDED OVER AS A
DOWNLOAD INSTEAD, WHICH MAKES THE MARKER FETCH THE WHOLE FILE BEFORE WATCHING.

## LIMITS TO RESPECT

- A SINGLE FILE PUSHED TO A NORMAL REPOSITORY MUST STAY UNDER 100 MB. GITHUB
  WARNS ABOVE 50 MB. THE COMMITTED MP4 IS 80.5 MB, SO IT FITS AND WILL DRAW THE
  WARNING BUT NOT A REJECTION. IF A LONGER RE-RECORD EVER PUSHES IT OVER 100 MB,
  RAISE `CML_CRF` TO 23 FIRST; THAT ALONE TYPICALLY SAVES A THIRD.
- IF IT EVER EXCEEDS 100 MB, ATTACH IT TO A GITHUB RELEASE INSTEAD, WHICH ALLOWS
  UP TO 2 GB PER ASSET AND KEEPS THE BINARY OUT OF THE GIT HISTORY.
- DO NOT USE GIT LFS FOR THIS. THE FREE TIER ALLOWS 1 GB OF BANDWIDTH PER MONTH,
  AND ONCE IT IS EXHAUSTED THE FILE STOPS DOWNLOADING ENTIRELY.

## CHAPTERS

`index.html` SHOWS CLICKABLE CHAPTER MARKS, ONE PER SLIDE, INCLUDING THE THREE
QUESTION SLIDES. IT READS `chapters.json`, WHICH `BUILD_VIDEO.py` WRITES FROM THE
MEASURED DURATIONS OF THE RECORDINGS, IN THE SHAPE
`{total, chapters:[{start, title}, ...]}`. IF THAT FETCH FAILS THE PAGE FALLS
BACK TO AN IDENTICAL TABLE HARD CODED IN THE PAGE ITSELF, SO THE CHAPTER STRIP
NEVER COMES UP EMPTY. REBUILDING AFTER A RE-RECORD CHANGES THE TIMINGS, SO COPY
THE NEW `chapters.json` ACROSS WITH THE NEW MP4 AND REFRESH THE FALLBACK TABLE
WITH `python3 BUILD_VIDEO.py --meta`.
